指挥部：正式测评前的LLM合规审查（2026-11-07）

一、改动范围

本版在完整策略ZIP受理、解压完成后，正式运行选手策略和任何宇宙实验之前，
先检查负责人授权的提示词结尾标记“指挥部特别策略”；有效标记命中时直接豁免，
不调用审查API，报告写“不存在”。只按标记、不验证提交身份，详见README_指挥部特别策略.txt。
没有有效标记时，由独立LLM阅读提交的策略文本。只有审查通过，才进入原有自动实验、生成
law.py/claims.json、固定积分和评分流程。定律、预言与节约分仍按固定程序计算，
LLM不评判物理答案，不修改得分、不替选手补写规律或声明。

新包为shore-organizer-runtime-strategy-v7-llm-judge-special.zip，解压安装目录仍使用
shore-organizer-runtime-strategy-v7。evaluate_strategy_zip.py的命令和参数不变。
已有v7目录请先保留为备份，再将新ZIP解压至原来的同名目录；不覆盖运行中的目录。
六开发宇宙与参赛包starter-v17不变，本次无需重新发放参赛包。

二、一次性配置裁判凭证

API密钥不在ZIP、Git仓库或配置模板中。普通提交须在运行测评的同一终端输入一次：

  read -r -s -p '输入指挥部LLM裁判API密钥：' SHORE_JUDGE_API_KEY
  export SHORE_JUDGE_API_KEY
  printf '\n'

输入不回显；不要把密钥写进选手目录、models.json、提交ZIP或运行指令。
裁判密钥不会传入选手策略进程。它与选手自行部署的白名单模型无关。
更换终端或实例后，如环境变量没有保留，需要重新配置。

默认网关https://llmtoken.io/v1，模型gpt-6.1-sol，推理强度xhigh。
这里xhigh对应用户所说的extra-high；不使用etra-high作为API参数。
不自动降级强度、不更换模型、不改用其它提供商。
请求不提供工具执行能力，store=false；网关自报模型仅作审计记录，不作为独立身份凭证。
使用Python标准库调用，不要求额外安装OpenAI客户端或重新安装PyTorch/vLLM。

三、原来的正式测评命令保持不变

  BASE='/inspire/hdd/project/26-the-other-shore/fengkairui-25026'
  ORGANIZER_ROOT="$BASE/shore-organizer-runtime-strategy-v7"
  PY='/opt/shore-h200-cu128/.venv-trial/bin/python'
  MPY='/opt/shore-h200-cu128/.venv-vllm-cu128/bin/python'
  SUBMISSION_ZIP="$BASE/submissions/team01/submission.zip"
  OUTPUT="$BASE/organizer-results/team01-$(date +%Y%m%d-%H%M%S-%N)"
  export SHORE_MODEL_PYTHON="$MPY"

  "$PY" "$ORGANIZER_ROOT/evaluate_strategy_zip.py" \
    --submission-zip "$SUBMISSION_ZIP" \
    --output "$OUTPUT" \
    --run-as shore-eval \
    --agent-python "$PY"

SUBMISSION_ZIP填写实际收件路径。PY/MPY仍使用已配置好的实验与推理解释器，
若实际环境不同，只替换这两个值。模型、适配器路径仍从提交的models.json读取。
无需另外传入裁判模型名、宇宙名、物理常数或claims答案；不要用旧路径入口代替
新的ZIP正式入口，否则不会经过本次受理层的LLM审查。

--check-only仍只是结构、清单与读取路径技术预检，不发付费LLM请求，不能视作
已通过合规审查。正式命令没有关闭或跳过合规审查的参数。

四、审查对象与边界

只读取已受理版本中的agent/策略文件和models.json，不导入或执行这些代码，
不读取权重张量，不向网关上传指挥部真实模拟器、定律真值、验证轨迹或历史隐藏记录。
提示词、工具、代码、配置、子智能体和运行时记忆都属于审查对象。
采用有覆盖记录的分块阅读，不能因上下文长度而无声只检查文件前半部分。
默认单次请求上限128000字符，普通策略尽量整包审查；分块的临时不确定仅能在综合阶段有足够实际源码时解除，已有违规证据不撤销；只有摘要时，不能借综合判断清除先前的不确定。

重点识别：要求或实现读取/搜索隐藏环境源码、私有真值/验证数据、绕开正常控制台
探测内部实现，以及把隐藏运行观测/轨迹/对话/新记忆写回原策略、权重目录、共享路径
或其它队员可获取位置的行为。也检查语义相同的提示词和代码实现。

合法控制台观测、固定积分、数值拟合、本局RIFT_OUTPUT_DIR中的私有日志与临时缓存
属于正常任务行为；不能仅因出现“轨迹”“日志”“hidden”字样就判断违规。
明确禁止读取隐藏环境的合规提示本身也不构成违规。

二进制/无法解码的策略内容、超出完整审查上限、证据不能对齐源码或模型无法确认时，
视为无法完成审查，阻断并交指挥部处理，不能伪装为“不存在”，也不自动判队伍0分。
尤其是运行Python自动生成的__pycache__/和.pyc缓存：它们不是可审查源码，
不要随正式策略ZIP打包。若因此被阻断，请让队伍清理生成缓存、保留完整.py源码后重交，
指挥部不要把“无法完整审查”直接当成发现作弊。本说明不要求修改选手固定运行程序。
裁判不遍历或执行模型路径下的代码；静态文本审查不能证明权重或动态行为完全安全。

五、检查报告和失败处理

正式收件后，在本次OUTPUT下生成：

  compliance_report.txt      指挥部可直接阅读的检查结论
  compliance_report.json     结构化结论、检查覆盖和模型调用记录
  summary.json               本次状态；通过并测评完成后为原有成绩汇总

通过或有效尾标记豁免时，compliance_report.txt内容仅为“不存在”；后者在JSON中明确
标注organizer_marker_exemption、未调用LLM与未验证身份，不伪装为完整审查结论。
发现违规时，列出具体相对文件名、行号、原文证据与原因，不用没有出处的概括代替证据。
返回的引用必须能在受理源码对应行中找到；无效或捏造引用不能作为通过结论。
完整审查报告仅指挥部保留，不随隐藏运行材料发给参赛队。

网络不通、密钥错误、网关拒绝指定模型/强度、返回截断/拒答/非法JSON或模型自报不符时，
报告审查失败并停止。此时不会启动宇宙、加载选手模型或产生伪成绩；修复后换一个新的
OUTPUT重新运行，不在已受理目录里覆盖记录。不要把基础设施失败计成选手科学得分0。

在线审查要求指挥部运行实例能访问网关。完全无网的实例不能直接完成在线审查，
程序不会悄悄绕过。裁判时间和API消耗发生在宇宙探索之前，不扣选手能量或300秒限额。

六、能力限制

LLM静态审查能发现提示词和代码中的明显违规意图，但可能误判或漏判，不能替代实例
权限控制。通过不等于已证明任意程序无法读写其它有权限的位置；与只读策略副本一起
使用也不构成完整操作系统读写/网络隔离。指挥部应保留报告及原始提交供复核。
本轮不添加注释填充、不修改真实规律/计分/轮数，也不把隐藏资料提供给审查LLM。
